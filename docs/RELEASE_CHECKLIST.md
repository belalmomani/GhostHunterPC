# قائمة التحقق لإصدار Windows

## إعداد الإصدار الذي تم التحقق منه

- [x] إطار العمل: `net10.0-windows`.
- [x] معرّف التشغيل: `win-x64`.
- [x] بناء التطبيق بإعداد `Release` قبل النشر: نجح بلا تحذيرات أو أخطاء.
- [x] نشر مستقل ذاتي الاحتواء (self-contained)، ملف تنفيذي مفرد، مع تضمين المكتبات الأصلية للاستخراج الذاتي.
- [x] التحقق من وجود `GhostHunterPC.exe` وموارد `Resources\UiStrings.ar.json` و`Resources\UiStrings.en.json`.
- [x] دليل النشر: `artifacts\publish\win-x64\`؛ حجم الملف التنفيذي 140,055,628 بايت، وحجم المخرجات الإجمالي 140,177,659 بايت.
- [ ] اختبار تشغيل النسخة المنشورة فعليًا على جهاز Windows x64 نظيف؛ لم يُجرَ هنا.
- [ ] التوقيع الرقمي؛ لم يتوفر مفتاح توقيع ولم تُوقّع النسخة.
- [ ] إنشاء مثبت للمستخدم النهائي.
- [ ] رفع الإصدار إلى GitHub؛ لم يُنشأ مستودع ولم يُرفع شيء.

## خطوات الإصدار قبل التوزيع

1. راجع فرق المصدر والوثائق، وتأكد من عدم تضمين أسرار أو إعدادات أو سجلات مستخدمين.
2. شغّل `dotnet restore .\GhostHunterPC.sln` ثم `dotnet build .\src\GhostHunterPC\GhostHunterPC.csproj --configuration Release`.
3. انشر `win-x64` self-contained كما هو موضح في [تعليمات التثبيت والبناء](./INSTALLATION_AR.md).
4. شغّل `GhostHunterPC.exe` المنشور على جهاز Windows x64، وتحقق من التشغيل واللغة وموارد JSON والقراءة/الحفظ المحلي.
5. إذا تقرر إنشاء مثبت، اختر أداة مثبت Windows مناسبة (مثل WiX Toolset أو Inno Setup)، وثبّت إصدار الأداة وإعداداتها في عملية الإصدار، ثم اختبر التثبيت والإزالة والترقية. لم يُنشأ Setup.exe أو MSI أو MSIX في هذا الإصدار.
6. وفّر توقيعًا رقميًا عبر شهادة موثوقة وإدارة آمنة لمفتاحها إذا تطلب التوزيع ذلك. لا تستخدم مفتاحًا غير موجود أو تضعه في المستودع.
7. راجع الحجم وبصمة الملفات الناتجة، وسجّل إصدارات SDK وأوامر البناء والنشر في إعلان الإصدار.
8. لا تنشر إلى GitHub إلا بعد موافقة مالك المشروع ومراجعة الملفات المراد رفعها. استخدم GitHub Secrets عند الحاجة إلى أسرار CI، وليس ملفات المشروع.

لم تُنفذ عملية إنشاء مثبت أو توقيع أو رفع في هذه المهمة.
