# تقدم المشروع

## الجزء 1: التحقق من البيئة وتأسيس المشروع

- أُنشئ حل `GhostHunterPC.sln` ومشروع WPF في `src/GhostHunterPC`.
- يستهدف المشروع `net10.0-windows` ويستخدم WPF.
- أُضيفت واجهة أولية ثابتة بلا وظائف متقدمة أو تغييرات على النظام.
- أُنشئت وثائق التأسيس وملف `.gitignore`.
- لم يُعثر عبر استعراض مساحة العمل على حل أو مشروع سابق قبل التأسيس.

## التحقق

- عند تأسيس الجزء 1 كان نظام التشغيل المعلن لمساحة العمل Windows.
- في ذلك الوقت تعذّر استعلام إصدار Windows و.NET SDK أو تنفيذ البناء بسبب عدم توفر الطرفية.
- جرى التحقق لاحقًا من النظام وSDK والبناء كما هو موثق في نتيجة التحقق أدناه.

## نتيجة تحقق لاحقة

في الجزء 2 أصبح تشغيل .NET CLI متاحًا، واكتمل بناء الحل بنجاح باستخدام هدف Windows/WPF دون تحذيرات أو أخطاء؛ وبذلك تأكد توفر أدوات الاستهداف اللازمة للبناء. أظهر `dotnet --info` وجود SDK 10.0.113 وWindows 10.0.19045 وWindows Desktop Runtime 10.0.13.

## الجزء 2: الواجهة الاحترافية باستخدام WPF وMVVM

- استُبدلت الواجهة التأسيسية بلوحة رئيسية قابلة لتغيير الحجم مع قائمة جانبية من عشرة أقسام.
- أُضيف تنقل فعلي بين الأقسام عبر ViewModels وأمر MVVM، مع قالب محتوى مشترك لتجنب تكرار الصفحات.
- أُضيف تبديل لغة الواجهة بين العربية RTL والإنجليزية LTR، وتبديل فوري بين لوحتي الألوان الداكنة والفاتحة.
- بطاقات لوحة التحكم تعرض حالات صريحة مثل «لم يُنفّذ بعد» و«لا توجد نتائج» بدل أرقام افتراضية.
- فُصلت خدمات اللغة والمظهر عن ViewModels، وأُضيفت نماذج عرض قابلة للإشعار.
- لم تُضف ميزات فحص أو تعديل ملفات أو إعدادات للنظام.

## تحقق الجزء 2

- تمت مراجعة ملفات XAML وC# المحفوظة ومطابقة عناصر التنقل ومفاتيح اللغة يدويًا.
- نُفذ `dotnet build .\GhostHunterPC.sln` بنجاح: صفر تحذيرات وصفر أخطاء.
- أكد بناء WPF نجاح ترجمة XAML وربطها وقت البناء؛ لم تُجرَ اختبارات تشغيل تفاعلية للواجهة.

## الجزء 3: لوحة التحكم ومعلومات الجهاز

- أُضيفت خدمة مستقلة للقراءة فقط تجمع اسم Windows وإصداره ومعمارية النظام، ومعلومات المعالج، والذاكرة الفعلية المتاحة والإجمالية، والأقراص المحلية الجاهزة ومساحاتها، ومدة تشغيل النظام.
- تستخدم الخدمة سجل Windows للبيانات الوصفية وواجهة `GlobalMemoryStatusEx` للذاكرة وواجهات .NET للأقراص ومدة التشغيل؛ لا تتطلب صلاحيات مدير ولا تغيّر إعدادات أو ملفات.
- أُضيف تحديث تلقائي عند فتح التطبيق وزر تحديث يدوي، مع حالات تحميل ونجاح جزئي وأخطاء واضحة.
- تعرض لوحة التحكم وقت آخر قراءة ناجحة لمعلومات الجهاز خلال جلسة التطبيق، وتوضح صراحةً أن فحص النظام نفسه لم يُنفّذ بعد.
- تعرض الحقول غير المتاحة «غير متاح»، ولا تعرض نتائج تجريبية أو أرقامًا مختلقة. عند تعذر قراءة قسم أو قرص، تبقى البيانات المتاحة ويُعلن النقص.
- كشف البناء الأول غياب استيراد `System.IO`، وأُصلح السبب.
- اكتمل البناء النهائي بعد جميع التعديلات: `dotnet build .\GhostHunterPC.sln --no-restore`، بنجاح وصفر تحذيرات وصفر أخطاء.
- شمل التحقق وقتها ترجمة XAML وربطها؛ أُضيف اختبار التشغيل والاختبارات الآلية في الجزء 4.

## الجزء 4: اختبار التشغيل ومحقق الملفات

- فُحص الحل والوثيقتان قبل الاختبار. مساحة العمل ليست مستودع Git، لذا تعذّر استخدام `git status`.
- شُغّل تطبيق WPF فعليًا؛ ظهرت نافذة `GHOST HUNTER PC` وبقي التطبيق مستجيبًا خلال الاختبارات دون انهيار. لم تظهر أخطاء مرتبطة بالتطبيق في سجل أحداث Windows.
- اختُبر التنقل تفاعليًا عبر UI Automation على الصفحات العشر: لوحة التحكم، فحص الجهاز، محقق الملفات، منظم الملفات، الملفات المكررة، مراقبة الجهاز، بصمة الجهاز، الخط الزمني، التقارير، والإعدادات.
- اختُبر تبديل اللغة والمظهر بعد إصلاح خلل مثبت: لم يكن إشعار تغيير اللغة يحدّث تسمية زر المظهر. بعد الإصلاح ظهر اسم الزر بالإنجليزية، وعمل التبديل بين المظهرين.
- اختُبر التحديث اليدوي لمعلومات الجهاز. ظهرت بيانات فعلية من هذا الجهاز: Windows 10 Pro (22H2، البناء 19045)، المعمارية X64، معالج Intel Pentium B950، 5.9 GiB ذاكرة، القرصان C: وD: وسعتهما، ومدة تشغيل النظام. عُرض عدد المعالجات المنطقية، وكانت الأنوية الفيزيائية غير متاحة.
- أُضيف مشروع اختبار دخان بلا حزم خارجية في `tests/GhostHunterPC.SmokeTests`. اجتاز 9 تحققّات لخدمة معلومات الجهاز وثوابت الذاكرة والأقراص ومدة التشغيل والتوطين.
- أُضيف مصدر أقراص قابل للاستبدال لاختبار الحالات الطرفية دون لمس الجهاز: قرص غير جاهز، واستثناء قراءة، وبيانات سعة غير متسقة. اجتازت الحالات الاختبار مع بقاء القرص السليم في النتائج وعدم انهيار الخدمة.
- قرأت الخدمة قرصي C: وD: الفعليين دون أقسام متعذرة. لم يُجرَ تغيير على الأقراص.
- فُحص سجل أحداث Windows بحثًا عن أخطاء مرتبطة بالتطبيق ولم تُعثر أخطاء. لم يكن مصحح أخطاء VS Code متصلًا، لذا لم يُلتقط سجل Output/Debug مباشرة؛ ولم يظهر استثناء أو انهيار في اختبار التشغيل.
- اجتاز اختبار الدخان بعد إضافة حالات القرص المصطنعة: `dotnet run --no-restore --project .\tests\GhostHunterPC.SmokeTests\GhostHunterPC.SmokeTests.csproj`؛ النتيجة 9 تحققّات ونجاح جميع حالات الأقراص المحاكية.
- فشل بناء نهائي أول بصفر تحذيرات وأخطاء ومن دون سبب ظاهر في مخرجاته؛ أُعيد البناء بمخرجات تفصيلية وعلى عقدة واحدة للتحقق.
- اكتمل `dotnet build .\GhostHunterPC.sln --no-restore --verbosity normal -m:1` بنجاح، بصفر تحذيرات وصفر أخطاء، وشمل التطبيق ومشروع الاختبارات.

### محقق الملفات

- أُنجزت ميزة محقق الملفات وربطها بالتنقل والواجهة وViewModels. لا يبدأ الفحص تلقائيًا؛ يختار المستخدم مجلدًا، ويجري التطبيق الفحص محليًا دون إرسال محتوى أو حذف أو عزل.
- تعرض النتائج الاسم والمسار والحجم والامتداد وتاريخ التعديل، مع تعرف تواقيع شائعة للملفات وتوضيح اختلاف النوع المكتشف عن الامتداد. تدعم القائمة البحث وفرز الأعمدة.
- يعرض التطبيق حالة التوقيع الرقمي والناشر عبر WinVerifyTrust عند توفره. يُستخدم التحقق دون جلب معلومات من الإنترنت؛ وتظهر حالات غير الموقع وتعذر التحقق منفصلة.
- أُضيف حساب SHA-256 بطلب المستخدم، وفتح موقع العنصر في مستكشف Windows، وإلغاء الفحص، ومؤشر تقدم، وأخطاء وصول لا توقف بقية الفحص.
- تعرض التنبيهات سبب المؤشر بوضوح ولا تدعي اكتشاف البرمجيات الخبيثة؛ فالنوع المجهول أو غياب التوقيع ليس دليلًا على الضرر.
- اختبر اختبار الدخان SHA-256 لمحتوى `abc` والملف الفارغ بمخرجات معروفة، كما اختبر اختلاف امتداد صورة PNG عن محتواها، والتحذير غير الجازم، واستمرار الفحص عند تعذر قراءة ملف.
- اكتمل `dotnet build .\GhostHunterPC.sln --no-restore --verbosity minimal -m:1` بصفر تحذيرات وصفر أخطاء.
- اجتاز `dotnet run --no-build --no-restore --project .\tests\GhostHunterPC.SmokeTests\GhostHunterPC.SmokeTests.csproj` جميع الفحوص: 13 تحققًا إجمالًا، منها بصمتا SHA-256 معروفتان، وفحص ملف غير متاح مع استمرار فحص ملف آخر.

## الجزء 5: منظم الملفات الذكي

- أُضيفت خدمة تنظيم مستقلة وViewModel وصفحة مرتبطة بالتنقل. يختار المستخدم مجلدي المصدر والوجهة يدويًا، ولا يبدأ أي نقل أثناء إنشاء المعاينة.
- يصنف المنظم الصور والفيديو والصوت والمستندات وPDF والأرشيفات وملفات البرمجة والأنواع الأخرى اعتمادًا على تواقيع المحتوى، مع تحقق من النص قبل استخدام الامتداد كقرينة إضافية. يعرض دليل التصنيف لكل ملف.
- تدعم الخطة تجميعًا اختياريًا حسب سنة وشهر تاريخ التعديل، وتعرض قائمة الملفات والحجم الإجمالي وتعارض أسماء الوجهة.
- لا يبدأ التنفيذ إلا بزر تأكيد يتبعه مربع حوار موافقة. خيارات التعارض هي التخطي، أو إعادة تسمية الملف الجديد باسم فريد، أو الاستبدال بعد موافقة منفصلة مع الاحتفاظ بنسخة احتياطية.
- يُسجل كل نقل وتخطٍ وفشل. يدعم التراجع بعد التحقق من SHA-256 للملف المنقول والنسخة المستبدلة، ويرفض الاسترجاع إذا تغيرت الملفات أو تعذر التأكد من سلامتها.
- يتعامل التنفيذ مع إلغاء المستخدم والأخطاء لكل ملف، ولا يتبع الروابط الرمزية، ويرفض مجلدات Windows والبرامج المثبتة ويتجنب تداخل المصدر والوجهة.
- اختبر اختبار الدخان قواعد تصنيف المحتوى والامتداد، معاينة بلا تعديل، تعارض اسم، إعادة التسمية، الاستبدال والتراجع، مسارات السنة/الشهر، ورفض مجلد Windows.
- اكتمل `dotnet build .\GhostHunterPC.sln --no-restore --verbosity minimal -m:1` بصفر تحذيرات وصفر أخطاء.
- اجتاز `dotnet run --no-build --no-restore --project .\tests\GhostHunterPC.SmokeTests\GhostHunterPC.SmokeTests.csproj` عدد 23 تحققًا، شملت كل فئات التصنيف المطلوبة، أدلة المحتوى، المعاينة دون نقل، التعارض والتخطي وإعادة التسمية والاستبدال، التراجع الآمن ورفض التراجع بعد تغيير الملف، التنظيم حسب الشهر ورفض مجلد Windows.

## الجزء 6: الملفات المكررة والقديمة

- أُضيفت خدمة وViewModel وصفحة تفاعلية لتحليل مجلد يختاره المستخدم فقط، مع حالتي الملفات المكررة والملفات القديمة، وتقدم وإلغاء وأخطاء وحالات فارغة.
- تُجمع الملفات حسب الحجم أولًا، ولا تُحسب SHA-256 إلا للمجموعات المرشحة ذات الحجم المتساوي؛ لا يُستخدم الاسم لإثبات التطابق. تظهر المجموعات والبصمات والمسارات والأحجام وتواريخ التعديل.
- تقدير المساحة المحتملة يحسب حجم كل مجموعة ناقص نسخة واحدة محفوظة. يوصي التطبيق بنسخة للإبقاء ويمنع تحديدها للنقل؛ يتطلب نقل العناصر الأخرى اختيارًا يدويًا وتأكيدًا، ويستخدم سلة المحذوفات لا الحذف الدائم.
- قبل النقل إلى سلة المحذوفات يعيد التطبيق التحقق من بصمة SHA-256 ويرفض الملفات التي تغير محتواها منذ الفحص. يعرض لكل ملف نجاح أو خطأ ويتيح إلغاء العملية.
- قائمة الملفات القديمة افتراضيًا ستة أشهر، ويمكن تغيير المدة؛ وتوضح الواجهة أن تاريخ التعديل لا يثبت آخر استخدام، مع بحث وفرز واستبعاد مجلدات النظام والبرامج المثبتة افتراضيًا.
- اختبرت الحالات ملفات متطابقة بأسماء مختلفة، ومحتوى مختلفًا رغم تساوي الحجم والاسم، وحساب المرشحين حسب الحجم، والملفات القديمة، والمجلد الفارغ، وحماية مجلد Windows، ورفض نقل ملف تغيرت بصمته.
- اكتمل بناء الحل دون تحذيرات أو أخطاء واجتاز اختبار الدخان جميع 27 تحققًا.

## الجزء 7: مراقبة موارد الجهاز والعمليات

- أُضيفت خدمة جمع مستقلة عن الواجهة لقراءة استخدام CPU من عينات عدادات النظام، واستخدام RAM، وسعة الأقراص الثابتة ومساحتها المتاحة، وقائمة العمليات وPID واستخدام الذاكرة.
- جُمعت البيانات خارج واجهة المستخدم؛ أُضيف تحديث يدوي وتحديث دوري بفواصل قابلة للاختيار (1، 2، 5، 10 أو 30 ثانية) مع زر إيقاف. يعرض التطبيق حالة التحديث ووقت آخر قراءة والأخطاء، ويستمر في عرض البيانات المتاحة عند تعذر قراءة جزء منها.
- تدعم قائمة العمليات البحث بالاسم أو PID والفرز حسب الاسم وPID والذاكرة؛ تدعم قائمة الأقراص الفرز حسب الاسم والسعة والمتاح. عناوين الأعمدة مترجمة بحسب لغة التطبيق.
- أُضيفت رسائل واضحة للعمليات التي يتعذر الوصول إليها أو التي تنتهي أثناء القراءة. تُقرأ العمليات بصلاحيات المستخدم الحالية؛ لا يوجد خيار لإنهاء عملية ولا يجري إنهاء العمليات تلقائيًا.
- لا يبدأ أي فحص تلقائي للقرص؛ جمع معلومات الأقراص والعمليات يبدأ عند طلب المستخدم التحديث أو تشغيل المراقبة الدورية.
- أُضيفت اختبارات بمصدر بيانات وعمليات محاكاة: رفض الوصول لذاكرة عملية، انتهاء عملية أثناء قراءة اسمها، استمرار بقية النتائج، ظهور قائمة عمليات محدثة في العينة التالية، وحساب استخدام CPU (75%) من فروق عينتين معروفة.
- اكتمل `dotnet build .\GhostHunterPC.sln --no-restore --verbosity minimal -m:1` بنجاح، وصفر تحذيرات وصفر أخطاء، بما في ذلك ترجمة XAML.
- اجتاز `dotnet run --no-build --no-restore --project .\tests\GhostHunterPC.SmokeTests\GhostHunterPC.SmokeTests.csproj` جميع الاختبارات: 29 تحققًا إجمالًا، منها اختبارات المراقبة المحاكية.

## الجزء 8: PC DNA وPC Timeline

- أُضيف خط أساس محلي يُجمع عند ضغط المستخدم فقط، ويتضمن حقول النظام المتاحة وأسماء البرامج المسجلة كبرامج مثبتة وأسماء العمليات وPID وعناصر Run/RunOnce في السجل. تُحفظ أوقات جمع العناصر، وتُعرض حالات نقص القراءة.
- تدعم المقارنة عرض العناصر المضافة والمزالة والمتغيرة. لا تصنف التغييرات كاختراق؛ وإذا تعذرت قراءة فئة في اللقطة الحالية أو خط الأساس، لا تستنتج المقارنة إزالة أو إضافة عناصر تلك الفئة من العينة غير المكتملة.
- أُضيف سجل أحداث محلي يبدأ من تشغيل التطبيق: بدء التطبيق وإنشاء خط الأساس وإجراء المقارنة. يمكن للمستخدم يدويًا استيراد آخر 24 ساعة (حتى 50 حدثًا) من سجل Windows System عبر `wevtutil`، عند توفر الأداة والصلاحيات؛ يُحفظ مصدر الحدث ونوعه ووقته وتفاصيل وصفية، مع إزالة التكرار حسب رقم سجل Windows.
- تتيح واجهة الخط الزمني التصفية حسب نوع الحدث والتاريخ، وتعرض وقت الحدث والمصدر والتفاصيل. لا تدعي وجود تاريخ يسبق بدء التسجيل.
- تُحفظ البيانات في `%LOCALAPPDATA%\GhostHunterPC\pc-history.json` وتُصدر إلى JSON بمسار يختاره المستخدم. لا يخزن التطبيق محتويات الملفات ولا يرفع البيانات. تتضمن بعض البيانات أسماء البرامج والعمليات ومسارات عناصر بدء التشغيل، وقد تكون حساسة؛ توضح الواجهة ذلك للمستخدم.
- اختبرت خدمة السجل حفظ خط الأساس وأحداث المقارنة وإعادة تحميلهما، التمييز بين الإضافات والإزالات والتغييرات، التصدير، تجنب استنتاج إزالة عناصر الفئات التي تعذر الوصول إليها، وعدم الكتابة فوق سجل تالف بصمت.
- اكتمل `dotnet build .\GhostHunterPC.sln --no-restore --verbosity minimal -m:1` بصفر تحذيرات وصفر أخطاء، واجتاز اختبار الدخان جميع 34 تحققًا.

## الجزء 9: «نفّذها لأجلي»

- أُضيفت صفحة تعرض مهامًا ثابتة: تنظيم التنزيلات، الملفات الكبيرة، التكرارات، برامج بدء التشغيل، وحالة الجهاز. لكل مهمة خطة تشرح الإجراء والنطاق والبيانات المتأثرة والتراجع قبل المتابعة.
- لا تنفّذ الصفحة إلا إجراءات معرفة مسبقًا؛ لا تشغّل أوامر PowerShell/CMD أو نصوصًا حرة. تتطلب المتابعة تأكيدًا، ويمكن إلغاء الخطة قبلها. التنظيم والحذف/النقل الفعلي يظلان في الأدوات الأصلية ذات المعاينة والتأكيد والإلغاء الخاصة بها.
- رُبط تنظيم الملفات بمنظم الملفات، والتكرارات بخدمة SHA-256، وبرامج بدء التشغيل بخط أساس PC DNA، ومعلومات حالة الجهاز بخدمة القراءة الموجودة. تسجل المهمة والنتيجة أو الإلغاء محليًا ضمن PC Timeline، دون حفظ مسارات أو محتويات ملفات أو رفع البيانات.
- لا توجد خدمة مخصصة للعثور على الملفات الكبيرة؛ تعرض المهمة «غير متاحة» ولا تدّعي فحصًا لم يحدث.
- أُضيفت اختبارات دخان للتحقق من القائمة الثابتة، ورفض المهمة المجهولة أو المعدلة أو غير المتاحة، ورفض الإذن دون تأكيد.

## الجزء 10: التقارير والإعدادات والتعريب

- أُضيفت شاشة تقارير لنتائج معلومات الجهاز ومحقق الملفات والملفات المكررة ومراقبة الجهاز وتغييرات خطوط الأساس، مع تصدير CSV/JSON إلى مسار يختاره المستخدم. توضح التقارير عدم تنفيذ الفحص الشامل، وتتجنب المسارات وأسماء العمليات ومفاتيح/قيم تغييرات خطوط الأساس.
- PDF غير متاح لعدم وجود مكتبة مناسبة مضافة؛ لا توجد حزمة جديدة أو خدمة خارجية.
- أُضيف تخزين محلي لإعدادات اللغة والمظهر وفاصل المراقبة ومجلدات الاستثناء وتفضيل حفظ أحداث التطبيق في `%LOCALAPPDATA%\GhostHunterPC\settings.json`. تُطبق الاستثناءات في محقق الملفات وفحص التكرارات ومنظم الملفات. تعطيل أحداث السجل لا يحذف السجلات الموجودة أو خطوط الأساس.
- نُقلت مفاتيح الترجمة الـ319 الموجودة كلها إلى ملفي موارد JSON منفصلين للعربية والإنجليزية، وتُحمّل من مجلد موارد التطبيق. تتحدث القوائم والتسميات عند التبديل مع ضبط اتجاه RTL/LTR وثقافتي `ar-SA`/`en-US`.
- الإشعارات غير متاحة ومعلنة كذلك. الإعدادات والتقارير والسجلات تبقى محلية؛ لا توجد اتصالات رفع أو حفظ أسرار.
- أُضيفت اختبارات تبديل موارد اللغتين والثقافة، استمرار الإعدادات بعد إعادة التحميل، قواعد استثناء المجلدات، وتصدير JSON/CSV مع التحقق من تهريب الحقول.
- التحقق النهائي: نجح `dotnet build .\GhostHunterPC.sln --no-restore --verbosity minimal -m:1` بصفر تحذيرات وأخطاء. اجتاز اختبار الدخان 372 تحققًا، منها المرور على مفاتيح الترجمة الـ319 بكلتا اللغتين، وحفظ الإعدادات واستعادتها، وتطبيق الاستثناء على فحص المجلد، وتصدير CSV/JSON.

## الجزء 11: الاختبارات والمراجعة والإصلاح

- نُفذ `dotnet restore .\GhostHunterPC.sln` بنجاح؛ لم تتطلب المشاريع استعادة إضافية.
- نُفذ `dotnet build .\GhostHunterPC.sln --no-restore --verbosity minimal` بنجاح: صفر تحذيرات وصفر أخطاء، وبناء التطبيق ومشروع اختبار الدخان وترجمة XAML.
- فُحصت ملفات المشروع ومواضع WPF/XAML والتعامل مع الأخطاء والملفات والسجل والتزامن والإلغاء والصلاحيات والإجراءات المؤكدة والتوطين والخصوصية. لم تظهر مشكلة في المصدر قابلة لإعادة الإنتاج تستلزم إصلاحًا في هذا الجزء.
- شُغّل `dotnet test .\GhostHunterPC.sln --no-restore --verbosity minimal` وانتهى برمز خروج 0 دون عرض اكتشاف/نتائج اختبارات. مشروع اختبار الدخان تطبيق تنفيذي ولا يحتوي إطار اختبار أو حزمة اكتشاف؛ لذلك لا تُسجل هذه النتيجة على أنها نجاح اختبارات `dotnet test`.
- اجتاز `dotnet run --no-build --no-restore --project .\tests\GhostHunterPC.SmokeTests\GhostHunterPC.SmokeTests.csproj` جميع 372 تحققًا، بما فيها رفض الإجراءات غير المسموحة أو غير المؤكدة، وخدمات الملفات والتراجع والمراقبة، وخط الأساس والسجل، والتوطين والإعدادات والتقارير.
- محاولة `dotnet test --solution .\GhostHunterPC.sln ...` الأولى لم تُقبل بسبب صيغة خيار غير مناسبة (`MSB1001`)؛ أُعيد التنفيذ بالمسار الموضعي كما هو موضح في التقرير.
- لا يشمل تحقق هذا الجزء تشغيلًا تفاعليًا لنافذة WPF أو التغليف. الميزات غير المكتملة/غير المتاحة موثقة في [حالة الميزات](./FEATURE_STATUS.md).
- أُنشئ [تقرير البناء والاختبار](./BUILD_AND_TEST_REPORT.md) بالنتائج الفعلية والأوامر والمشكلات المتبقية. لم تُنفذ عملية تغليف.

- أُعيد التحقق ببناء التطبيق في `Release` قبل النشر: نجح بصفر تحذيرات وأخطاء. يستهدف المشروع `net10.0-windows`.

- أُنشئت تعليمات التشغيل والبناء وإعداد GitHub في [تعليمات التثبيت](./INSTALLATION_AR.md)، وقائمة التحقق للإصدار في [قائمة إصدار Windows](./RELEASE_CHECKLIST.md).
